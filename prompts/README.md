# prompts/

Every string TLC sends to Gemma 4 lives here. One file per prompt, YAML
frontmatter at the top tracking version + change date + which TS module
loads it. The runtime loader is [`lib/prompts.ts`](../lib/prompts.ts);
it strips the frontmatter and exports each prompt as a string constant.

If a school district, hackathon judge, or curious teacher wants to know
exactly what the model was told to do, this directory is the answer.

## Versioning

Each file's frontmatter carries:

```yaml
---
prompt: hunter.system
version: 1.0.0
last_changed: 2026-05-08
used_by: lib/personas.ts → HUNTER_SYSTEM_PROMPT
sent_to: Gemma 4, system role
phases: ["1-build", "3-package"]
---
```

When you change the prompt body, bump `version` per semver:

- **Major** (e.g. 1.0.0 → 2.0.0) — the persona's role or output schema
  meaningfully changed. Existing seeded gallery lessons may no longer
  represent the new prompt's behavior.
- **Minor** (1.0.0 → 1.1.0) — a new capability or instruction added
  without removing or contradicting earlier ones.
- **Patch** (1.0.0 → 1.0.1) — wording polish, typo, clarification that
  doesn't change semantics.

Update `last_changed` to today's date in `YYYY-MM-DD` form.

The git history is the long-form changelog. If you need a per-version
artifact (e.g. for reproducing a prior run), check out the commit that
last touched the file.

## Why markdown, not TypeScript

These files used to be string literals inside `lib/personas.ts`. Two
problems with that approach:

1. **Inspectability.** Anyone reviewing TLC's behavior had to read TS
   code to find the prompts. Auditors, teachers, and judges shouldn't
   need a dev environment.
2. **Drift.** The `PROMPTS.md` file at repo root was meant as
   documentation, but it was a copy of the strings — the kind of doc
   that decays the moment the strings change.

Now there's one source of truth (these `.md` files), the loader pulls
them at module load (Next.js outputFileTracing bundles them with the
serverless functions), and the version string is part of the file.

## What a prompt looks like end-to-end

For Hunter on a Phase 1 Build call, the system role sent to Gemma 4 is:

```
HUNTER_SYSTEM_PROMPT (hunter.system.md body)
   +
PHASE_1_BUILD_ADDENDUM (build.addendum.md body)
```

The user-turn content is built dynamically by `buildContext()` in
`lib/personas.ts` from the teacher's form input + (if provided) source
material. That dynamic context is **not** a prompt template — it's the
data the prompts operate on.

For the contradiction check, the system role is `CONTRADICTION_SYSTEM_PROMPT`
and the user content is a list of `(claim_id, lesson_definition,
[Wikipedia/Wikidata excerpts])` tuples generated by `lib/verify.ts`.
